# 기업 목록/검색 화면 — 디자인 핸드오프

`/companies` · 공개 기업을 검색어와 필터로 좁혀 보는 화면.

**디자인이 들어왔다** — Claude Design 의 **"플랜틀리 공개 검색 목록 페이지"** 가 정본이고 코드에
반영을 마쳤다. 아래 3절의 요소별 규칙은 그대로 유효하다(백엔드 계약에서 오는 것들이라 디자인이
바뀌어도 안 바뀐다). 무엇이 어떻게 달라졌는지는 9절에 적어 뒀다.

- 코드: `app/companies/page.tsx` · `components/CompanyList.tsx` · `CompanySearchForm.tsx` ·
  `CompanyFacets.tsx` · `Pagination.tsx` · `lib/companySearchParams.ts`
- 확인: `npm run dev` 후 <http://localhost:3000/companies> (백엔드 `local,seed` 프로필 필요)
- 같은 시스템 안에 있어야 할 형제 화면: 메인 **"플랜틀리 메인 화면 확정 4a"**,
  상세 **"플랜틀리 기업 상세페이지 v2"**. 이 화면은 그 둘 사이를 잇는 자리다.

화면별 정본 이름은 `CLAUDE.md` 의 "디자인" 절에 세 화면이 나란히 적혀 있다.

---

## 1. 이 화면의 성격

메인은 **큐레이션 지면**이고(스포트라이트·추천·최근 등록), 이 화면은 **찾으러 온 사람의 작업대**다.
같은 카드를 쓰지만 목적이 다르다.

- 메인에서 이리로 오는 길: 대분류 카드 4장, 격자 아래 "전체 기업 보기", 헤더 "기업 찾기",
  상세 화면의 빵부스러기("기업 찾기 / 분류명").
- 조건은 전부 **주소에 실린다**(`/companies?keyword=…&categoryIds=1&page=2`). 링크를 공유하면
  같은 결과가 열린다 — 이 화면에서 "지금 무슨 조건이 걸려 있는가"가 늘 보여야 하는 이유다.

## 3. 요소 인벤토리

각 줄의 "규칙"은 백엔드 계약이나 이미 내린 결정에서 오는 것이라, 디자인이 바꾸면 화면이 거짓말을 한다.

### 3.1 머리

| 요소 | 지금 | 규칙 |
| --- | --- | --- |
| 킥 라벨 | `COMPANY DIRECTORY` | 장식이다. 바꿔도 된다 |
| 제목 | `기업 찾기` | 헤더 메뉴·상세 빵부스러기와 같은 말이라 함께 바꾼다 |
| 설명 | "비공개로 돌렸거나 삭제된 기업은 나오지 않습니다" | 사실 안내다. 비공개·삭제 기업은 회색 처리가 아니라 **아예 빠진다** |

### 3.2 검색

| 요소 | 지금 | 규칙 |
| --- | --- | --- |
| 통합 검색 입력 | `.blueprint` 바 + `.srch` + 파랑 검색 버튼 | **띄어쓴 단어를 각각 AND** 로 훑는다("몰드 금형" = 둘 다 가진 기업). 이 성질이 자리표시자 문구에 들어 있다 |
| 고급검색 토글 | `<details>` · "고급검색 · N칸 입력됨" | 값이 있으면 열린 채로 시작한다 |
| 고급검색 9칸 | 기업명 / 한 줄 소개 / 상세 소개 / 대표자명 / 주소 / 상세 주소 / 프로젝트·성과·협력사 / 보유 장비 / 취급 소재 | 백엔드 필드와 1:1. **늘리거나 합칠 수 없다**. "프로젝트·성과·협력사"는 한 필드가 세 컬럼을 훑어서 라벨이 길다 |
| 제출 버튼 | 바에 하나, 고급검색 안에 하나 (같은 form) | 통합 검색어와 고급검색은 **함께** 제출된다. 백엔드가 둘을 AND 로 걸기 때문에 따로 내보내면 앞의 검색어가 남아 있는 걸 화면이 감추게 된다 |
| 고급검색 비우기 | 9칸을 비우고 곧바로 다시 검색 | 비우기만 하면 화면과 결과가 어긋난다 |
| 인기 검색어 칩 | **없다** | 메인 히어로에만 있다(집계 API 가 없어 고정 예시라, 작업대에까지 놓지 않았다) |

### 3.3 조건 칩 줄

| 요소 | 지금 | 규칙 |
| --- | --- | --- |
| 칩 | `검색어: 몰드 ×` / `보유 장비: CNC ×` / `분류: 제조 솔루션 ×` | 누르면 그 조건만 빠진다. **패싯 이름을 못 받았으면 `분류: #12` 로 보여 준다** — 감추면 걸린 필터가 화면에서 사라진다 |
| 조건 모두 지우기 | 텍스트 링크 | 조건이 하나라도 있을 때만 **버튼이** 나타난다 |
| 빈 상태 | "선택된 조건이 없습니다 — 검색창 또는 왼쪽 필터를 이용하세요." | **띠 자체는 조건이 없어도 남는다.** 자리가 생겼다 사라지면 첫 조건을 걸 때 아래 지면이 통째로 밀리고, "지금은 아무 조건도 안 걸렸다"를 말해 줄 자리도 없어진다 |

### 3.4 패싯 사이드바

세 축의 **결합 규칙이 서로 다르다.** 지금은 각 묶음 제목 아래 한 줄 설명으로 알린다.

| 축 | 개수(시드 기준) | 결합 규칙 | 지금 |
| --- | --- | --- | --- |
| 분류 | 대분류 4 · 전체 143 노드(depth 1~3) | 고른 것 중 하나만 맞아도 됨(OR) + **후손 서브트리까지** | 접이식 체크박스 트리. **글자는 펼치고 접기만, 고르기는 체크 상자에서만** (아래) |
| 업종 | 24 | OR | 평면 체크박스, 260px 스크롤 |
| 인증 | 8 (경영시스템 3 / 산업특화 2 / 시장진입 3) | **묶음 안 OR · 묶음끼리 AND** | type 별로 상자에 묶는다. 높이를 막지 않아 안쪽 스크롤이 없다. 이름 뒤 괄호는 풍선(`.hint`)으로 접는다 |

**사이드바는 200px 다.** 240px 이던 것을 줄였다 — 폭을 정하고 있던 건 인증 이름 뒤의 괄호
(`SQ 인증 (자동차 OEM 협력사 품질)`)라, 그 설명을 풍선으로 접고 나니 남는 이름은 훨씬 짧다.
줄어든 40px 은 결과 격자가 가져간다. 풍선은 마우스를 올리거나 그 줄에 키보드 포커스가 오면 뜨고,
설명 자체는 라벨 안에 sr-only 로 남아 있어 체크박스의 이름은 여전히 괄호까지 온전하다.

**조건을 만지는 동안 스크롤은 제자리에 있다.** 체크를 하나 켤 때마다 화면이 맨 위로 튀면 조건을
두세 개 걸 수가 없다(방금 누른 줄이 사라진다). 대신 오른쪽 아래에 "맨 위로" 버튼이 스크롤과 상관없이
늘 떠 있다 — 나타났다 사라지면 찾게 되고, 보이는 기준이 또 하나의 규칙이 된다. 페이지 이동만은
예외로 맨 위로 올린다.

**분류 트리의 조작은 두 갈래로 갈라 놓았다.**

- **글자 = `+`/`-`.** 누르면 하위가 펼쳐지고 다시 누르면 접힌다. 체크는 걸리지 않는다.
  하위가 없는 분류(143개 중 118개)는 펼칠 게 없으므로 글자를 눌러도 아무 일도 하지 않는다.
- **고르기는 14px 체크 상자에서만.** 한 줄이 두 가지 일을 하면 "펼치려고 눌렀는데 필터가 걸리는"
  일이 생긴다.
- **상위를 골라도 하위 상자는 따라 켜지지 않는다.** 결과로는 이미 따라온다(후손 서브트리까지
  잡는다) — 화면에서 한 번 더 그려 봐야, 하위 id 를 주소에 실으면 결과는 그대로인 채 주소와 조건
  칩만 수십 개로 불어나고(제조 솔루션이면 50개), 켜진 채 잠그면 "켜져 있는데 끌 수는 없는 상자"가
  남는다. 한 번 만들어 보고 되돌렸다. 상자는 각자 걸린 것만 보여 주고, "하위까지 함께 찾는다"는
  묶음 제목 아래 한 줄이 맡는다.

- "대분류를 고르면 소분류만 단 회사도 나온다"가 이 화면에서 제일 설명하기 어려운 규칙이다.
  지금은 "고른 분류의 하위까지 함께 찾습니다" 한 줄로 때웠다 — 더 나은 표현이 나오면 그쪽이 낫다.
- 인증의 AND 는 사용자가 여럿 고를수록 결과가 급격히 줄어드는 축이다. 시드 기준으로 경영시스템 안에서
  둘을 고르면 12 → 23건으로 **늘고**, 경영시스템 하나 + 시장진입 하나를 고르면 12 → **1건**으로 준다.
  같은 체크박스가 정반대로 움직이므로 다른 두 축과 **다르게 보여야** 한다(지금은 문구뿐이라 구분이 없다).
- 선택 개수와 "지우기"는 묶음 제목 줄에 붙어 있다.

### 3.5 결과

| 요소 | 지금 | 규칙 |
| --- | --- | --- |
| 제목 | 조건 있으면 `검색 결과`, 없으면 `전체 기업` | |
| 개수 | `총 29개 · 1/2 페이지` | `pageInfo` 에서 온다. 화면이 세지 않는다 |
| 정렬 표기 | `정렬 · 추천 노출 → 최신 등록` (오른쪽 끝, 12px) | **정렬 선택 UI 를 만들면 안 된다.** 기본 정렬(스팟라이트 → 추천 → 최신)은 편의가 아니라 "어떤 검색어·패싯에도 유료 기업을 상위로"라는 요금제 계약이라, 사용자가 끌 수 있는 스위치가 되면 안 된다. 무슨 순서인지 **적기만** 한다 |
| 카드 | 메인과 같은 `CompanyCard`(`.pcard`) | 3열 격자, 18px 간격. 카드 자체를 이 화면용으로 다시 그릴 필요는 없다 |
| 페이지 이동 | 이전 / 번호 최대 7개 / 다음 | 메인의 "더 보기"(이어 붙이기)와 다른 게 맞다. 조건과 페이지가 주소에 실리므로 3페이지를 가리키는 주소가 있어야 한다 |
| 한 페이지 | 24건 (3열 × 8줄) | 백엔드 상한은 100. 주소에 싣지 않는 고정값이다 |

## 4. 디자인해야 하는 상태 6종

목록 화면은 "결과가 있는 화면"만으로는 절반이다. 아래가 실제로 나타나는 상태다.

| 상태 | 언제 | 지금 |
| --- | --- | --- |
| 결과 있음 | 기본 | 카드 격자 + 페이지 이동 |
| 불러오는 중 | 조건이 바뀔 때마다 | 카드 자리표시자 6장(`CompanyPlaceholder`). 사이드바는 이미 그려진 채로 남는다 |
| 조건에 맞는 게 없음 | 총 0건 | 점선 판 + "조건에 맞는 기업이 없습니다" + 힌트 + **조건 모두 지우기** |
| 페이지가 범위 밖 | 주소를 고쳤거나 오래된 링크 (`?page=99`) | "2페이지까지만 있습니다." + **첫 페이지로**. 앞의 빈 상태와 **다른 화면이어야 한다** — 여기에 "필터를 풀어 보세요"를 띄우면 아무 상관 없는 안내가 된다 |
| 공개 기업이 아예 없음 | 시드 전 | "공개된 기업이 없습니다" (버튼 없음) |
| 요청 실패 | 백엔드가 꺼져 있음 | 실선 판 + 백엔드가 준 한국어 문장 + **다시 시도** |

추가로 **패싯 선택지를 못 받은 상태**가 따로 있다 — 결과는 정상인데 사이드바만 스켈레톤 4줄이다
(선택지를 못 받아도 목록은 보여야 하므로 화면을 막지 않는다).

그리고 카드의 좋아요·즐겨찾기를 **비로그인으로 눌렀을 때** 알림 한 줄이 조건 칩 줄 아래에 뜬다
(`.bg-brand-soft` 판). 지금은 그냥 한 줄이라 자리가 눈에 안 띈다.

## 5. 아직 안 한 것 / 알고 있는 약점

- **좁은 화면.** `lg` 미만에서 패싯 세 묶음이 결과 위에 통째로 쌓여, 모바일에서 결과를 보려면
  한참 스크롤해야 한다. 접이식이나 시트로 바꿔야 하는데 디자인에도 좁은 화면이 없어 그대로 뒀다.
- 원본 디자인의 **모서리 등록 마크(`.corner`)와 방안지 격자(`.plate`)는 쓰지 않는다.**
  메인·상세에서 뺀 것과 같은 이유다 — 되살릴 거면 세 화면을 함께 되살린다.
- **카드(`CompanyCard`)는 손대지 않았다.** 디자인의 카드는 업종 라벨이 없고 칩 줄이 한 줄이지만,
  이 컴포넌트는 메인 격자와 공용이라 바꾸면 "메인 화면 확정 4a" 와 어긋난다.
- **사이드바가 따라오지 않는다**(sticky 아님). 결과를 내려 보다 필터를 바꾸려면 위로 올라와야 한다.
  한 번 `lg:sticky` 로 붙여 봤다가 되돌렸다 — 세 축을 다 그리면 사이드바가 **960px 남짓**이라
  (필터 머리 40 · 분류 접힌 상태 153 · 업종 260 스크롤 332 · 인증 439) 보통 노트북 뷰포트보다
  길고, 그러면 위에 고정된 채 아래쪽 인증 묶음이 화면에 영영 안 들어온다. 손이 닿지 않는 것보다
  올라오는 편이 낫다. 되살리려면 사이드바를 뷰포트 안에 들어오게 줄이는 게 먼저다.

인증 AND 는 디자인이 풀어 줬다(9절).

## 6. 없는 데이터 — 지어내지 않는다

메인·상세와 같은 규칙이다. 디자인이 그린 자리에 채울 값이 백엔드에 없으면 축을 바꾸거나 뺀다.

| 그리고 싶어지는 것 | 실제 |
| --- | --- |
| 정렬 드롭다운(추천순·최신순·인기순) | 정렬은 요금제 계약이라 **선택지가 없다**. 인기순은 집계 컬럼 자체가 없다 |
| 지역 필터 | 검색 쿼리에 지역 파라미터가 없다. 패싯은 분류·업종·인증 셋뿐이다 |
| 패싯 옆 "(12)" 결과 수 | 패싯별 건수를 주는 API 가 없다 |
| 카드의 조회수·문의수·평점 | 없다 |
| 저장한 검색 / 최근 검색어 | 없다 |
| 격자·리스트 보기 전환 | 카드가 한 종류다(리스트형 카드를 새로 그릴 거면 그것도 디자인 대상) |
| 페이지 크기 선택(12/24/48) | 고정 24. 넣으려면 주소 규칙부터 바꿔야 한다 |

## 7. 이미 있는 것 (다시 만들지 말 것)

`app/globals.css` 의 `@theme` 토큰과 `@layer components` 어휘를 그대로 쓴다. 색·폰트는 이름으로만
쓰고 컴포넌트에 hex 를 박지 않는다.

- 색: `brand` `brand-hover` `brand-soft` `brand-100…900` / `ink` `muted` `faint` / `line` `line-soft`
- 폰트: `font-heading`(Barlow Condensed → Noto Sans KR, 제목·라벨·숫자) / `font-body`(Noto Sans KR)
- 이 화면이 쓰는 클래스: `.blueprint` `.btn` `.btn-primary` `.btn-secondary` `.chip` `.chip.on`
  `.srch` `.field` `.kick` `.skel` `.pcard`(카드 안)
- 글자 크기는 **정수 px**. 원본에 11.5/12.5px 이 있으면 올림해서 쓴다(반 픽셀에서 획이 흐려진다)

새로 필요할 것 같은 어휘: 체크박스 줄, 패싯 묶음 제목, 페이지 번호 버튼, 빈 상태 판.
지금은 전부 Tailwind 유틸리티로 직접 짜 놨으니, 디자인이 정해지면 `@layer components` 로 올린다.

## 8. 확인용 주소

백엔드 시드(`local,seed`) 기준. 각 주소가 어떤 상태를 보여 주는지 함께 적는다.

| 주소 | 보이는 것 |
| --- | --- |
| `/companies` | 조건 없음 · 45건 · 2페이지 |
| `/companies?categoryIds=1` | 분류 하나 · 29건 · 트리가 펼쳐진 상태 |
| `/companies?categoryIds=1&page=2` | 마지막 페이지 · 카드 5장만 남은 격자 |
| `/companies?keyword=몰드 금형` | 통합검색 AND · 1건 |
| `/companies?equipment=CNC` | 고급검색 한 칸 · 18건 |
| `/companies?keyword=몰드 금형&equipment=CNC` | 조건 칩 2개 · 0건(빈 상태) |
| `/companies?page=99` | 범위 밖 페이지 상태 |
| `/companies?certificationIds=1&certificationIds=2` | 인증 **같은 묶음** 둘(경영시스템) · 23건 — 넓어진다(OR) |
| `/companies?certificationIds=1&certificationIds=6` | 인증 **다른 묶음** 둘(경영시스템+시장진입) · 1건 — 급격히 좁아진다(AND) |

카드 자체의 극단값은 시드 케이스로 확인한다 — `C20` 빈 컬렉션(칩 없는 카드), `C21` 최대치(칩 넘침),
`C22` 긴 이름(말줄임), `C16` 배지 없음.

## 9. 디자인 반영 (2026-08-22)

정본 **"플랜틀리 공개 검색 목록 페이지"** 를 코드에 옮겼다. 화면이 네 층으로 나뉜 게 가장 큰 변화다 —
머리띠(제목 + 검색) · 남색 조건 띠 · 안내 · 본문 2단. 앞의 세 층은 판 좌우 끝까지 붙는다.
"무엇을 찾는 중인가"와 "무엇이 나왔나"를 지면으로 가르기 위해서다.

| 자리 | 전 | 후 |
| --- | --- | --- |
| 머리 | 제목·설명이 세로로 쌓임 | 킥이 brand-700, 제목 옆에 설명이 붙고 검색까지 한 띠로 묶임 |
| 통합 검색 | 회색 테두리 바 | 테두리를 `ink/50` 으로 진하게. 이 화면에서 제일 먼저 손이 가는 칸이라 같은 회색 상자에 묻히지 않게 |
| 고급검색 | 맨 텍스트 토글 + 판 | 테두리 상자. 필터 아이콘 · "N칸 입력됨" 배지 · 접힌 채로도 무엇인지 알려 주는 오른쪽 한 줄. 9칸에 각각 자리표시자가 붙었다 |
| 조건 칩 | 흰 바탕 위 파란 칩 줄 | **남색 띠**. 칩이 `키 + 값`으로 갈라지고(`.qchip`) 해제는 동그란 × |
| 안내(비로그인) | 파란 글씨 한 줄 | 아이콘 + 문장 + **로그인 버튼**. 로그인만 하면 되는 실패일 때만 버튼이 붙는다 |
| 사이드바 | 그 자리에 고정 | 그대로 두었다. `lg:sticky` 로 붙였다가 되돌렸다 — 사이드바가 뷰포트보다 길어 아래쪽이 가려진다(5절) |
| 필터 머리 | 없음 | "필터" + **전체 지우기**(패싯만 비운다. 검색어는 남색 띠 몫). "필터"는 결과 머리의 "검색 결과"와 같은 h2 23px 이라 두 단의 구분선이 같은 높이에서 만난다. 부제 "분류 · 업종 · 인증"은 폭을 줄이며 뺐다(바로 아래 세 묶음 제목과 겹친다) |
| 체크박스 | 네이티브 | 14px 상자를 직접 그린다(`.ck` + `.bx`). 입력은 sr-only 로 살아 있어 키보드·스크린리더는 그대로 |
| 분류 트리 | `+`/`-` · 왼쪽 테두리 | inset 세로선(`.d2` `.d3`). 펼침 표시는 `+`/`-` 를 그대로 둔다(아래) |
| 인증 | type 별 소제목 | type 별 **상자**(`.certbox`) + 상자 사이에 **AND**. 3.4절에서 "다르게 보여야 한다"고 적어 둔 자리다 |
| 결과 머리 | 19px · "추천 노출 → 최신 등록" | 23px · 아이콘 + "스포트라이트 → 추천 노출 → 최신 등록" |
| 페이지 이동 | `.btn` 재활용 | `.pg` — 34px 정사각에 가까운 칸 |
| 빈 상태 | 한 판 | 아이콘 + 22px 제목 + 이유 + **조건 모두 지우기** / **인증 필터만 풀기**(인증이 실제로 걸렸을 때만) |
| 범위 밖 | 한 판 | `Page 99 / 2` 킥 + **첫 페이지로** / **N페이지로** |
| 실패 | 서버 문장이 제목 | 제목은 고정("목록을 불러오지 못했습니다"), 서버 문장은 본문 |
| 패싯 실패 | 조용히 빈 목록 | 이유 한 줄 + **다시 시도** |

### 디자인에서 뺀 것

- **조건 띠를 조건 있을 때만 띄우는 것.** 원본은 칩이 있을 때만 남색 띠를 그리는데, 그러면 첫
  조건을 걸 때 아래 지면이 통째로 밀린다. 띠는 늘 두고 안내 문구로 비워 둔다(3.3).
- **인증 묶음의 안쪽 스크롤.** 340px 로 막아 두면 상자 사이의 AND 가 잘려, 세 축 중 이 축만
  다르게 움직인다는 게 화면에서 사라진다. 8개뿐이라 페이지째로 내려 보면 된다.
- **모서리 등록 마크와 방안지 격자.** 원본에 다시 들어와 있지만 메인·상세와 같은 이유로 뺐다.
- **카드.** 원본은 업종 라벨이 없고 칩 줄이 한 줄인데, `CompanyCard` 는 메인 격자와 공용이라
  손대지 않았다(5절).
- **본문 라틴 폰트를 Barlow 로.** 원본 `--font-body` 는 Barlow + Noto Sans KR 인데, 본문 폰트는
  세 화면이 함께 쓰는 값이라 이 화면 하나를 보고 바꾸지 않았다.

### 분류 패싯 줄 끝의 숫자는 넣지 않는다

원본에는 분류 줄마다 작은 숫자가 붙어 있다(제조 솔루션 143, 금형 38 …). **회사 수로 읽으면 안 된다** —
패싯별 건수를 주는 API 가 없고, 6절대로 지어내지 않는다. 실제로 셀 수 있는 값은 하위 분류 수뿐인데
그건 사용자가 이 화면에서 궁금해할 숫자가 아니라(고르면 몇 곳이 나오는지가 궁금하지, 분류가 몇 갈래인지가
궁금한 게 아니다), 옆에 숫자가 붙어 있으면 결과 수로 읽힌다. **그래서 아예 뺐다.**

붙이려면 백엔드가 패싯별 건수를 함께 내려줘야 한다(`GET /companies` 응답에 facet count 추가).

### 펼침 표시는 세모가 아니라 `+`/`-`

원본은 `▸`/`▾` 인데 12px 자리에서 획이 뭉개져 표시가 있는지조차 잘 안 보인다. 같은 자리에서
형태가 또렷하고 "누르면 열린다"가 곧바로 읽히는 `+`/`-` 를 쓴다(`.cv`).
